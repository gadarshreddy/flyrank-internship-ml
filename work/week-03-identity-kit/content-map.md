# Portfolio Content Map

## One-line portfolio claim

I build practical AI/ML applications with Python and communicate
technical work through clear experiments, useful tools, and
evidence-based case studies.

## Primary audience

AI/ML engineering managers and technical recruiters evaluating
internship candidates.

## Site structure and section order

### 1. Home

1.  Hero: name, role focus, one-line claim.
2.  Featured projects: two or three strongest projects with links to
    code and case studies.
3.  Skills in context: Python, data analysis, machine learning,
    Git/GitHub, and relevant tools only where supported by evidence.
4.  About: short background and current learning focus.
5.  Contact: email and professional profile links.

**Primary CTA:** View projects\
**Secondary CTA:** Contact me

### 2. Projects

1.  Project overview and problem.
2.  Dataset or inputs.
3.  Approach and technical decisions.
4.  Evaluation/results, including limitations.
5.  What I learned and next steps.
6.  Links to repository, demo, or notebook when available.

**Primary CTA:** Read the case study\
**Secondary CTA:** View source code

### 3. About

1.  Short engineering-focused introduction.
2.  Current learning focus.
3.  Relevant coursework and technical interests.
4.  Links to GitHub and LinkedIn.

**Primary CTA:** View my work

### 4. Contact

1.  Short invitation for internship/project conversations.
2.  Email and professional links.

**Primary CTA:** Email me

## Evidence to collect before publishing

-   Screenshots or demos from real projects.
-   Repository links and readable READMEs.
-   Actual metrics/results, with methods and caveats.
-   Any certificates or awards that are relevant and verifiable.
-   A professional contact link.

## Content rules

-   Do not claim results that have not been measured.
-   Label prototypes and learning projects honestly.
-   Prefer concise explanations, code links, and evidence over generic
    skill claims.
-   Keep the same typography, palette, and spacing across pages.
